# Project map (frontend)

Where things live. Checked against the repo on the date of the last commit to this file. If a line here is wrong, fix the line in the same commit as the code change. Project rules are in `CLAUDE.md`; facts the code does not show are in `gotcha.md`.

## What this repo is
The signed-in SentrIA app and its sign-in screen: Next.js 16 (App Router), React 19, Tailwind v4, Supabase Auth in the browser, pnpm. Deployed on Vercel from `main`. It has no server routes of its own: every data call goes to the backend (`Sentria` repo, FastAPI on Render). The public marketing site is a separate repo (`sentria-landing-page`).

## Directories
- `app/`: Next.js entry only. `layout.tsx` (fonts, metadata, theme script), `page.tsx` (renders `AuthGate`), `t/[token]/page.tsx` (public field-task page, `noindex`), `robots.ts`, `opengraph-image.tsx`, error and loading pages, `globals.css`, `transitions.css`.
- `components/sentria/`: every screen and piece of the app, one file each (dashboard, tracking, calendar, pricing, admin, wholesalers, receiving, robo chat, dialogs). `components/ui/`: Button only.
- `lib/`: logic with no screen: API calls (`api.ts`, `crm.ts`, `answer.ts`), plans and entitlements, locale and i18n (`lib/i18n/fr.ts`, `en.ts`), value and cost helpers, upload, analytics, error tracking, Supabase client.
- `tests/unit/`: vitest. `tests/e2e/`: Playwright suites in their own package (`run-all.js`, `auth-mock.js`, `fakeapi.js`). `tests/smoke/`: post-deploy check. `tests/check_secret_scan.py`: tests the secret scanner.
- `scripts/`: icon builders (`build-*.mjs`), `check_secrets.py`, `check-i18n.mjs`, `validate-palette.mjs`, smoke scripts, `verify.sh`.
- `supabase/`: `001_accounts.sql` (accounts table and its row-level security) and the sign-up and reset email templates. Run by hand in the Supabase SQL editor.
- `docs/`: founder-facing notes (`rollback.md`, `status-page-plan.md`, `google-search-console.md`, `legal-audit.md`, setup notes).
- `public/`: images and icons. `test-data/`: sample CSVs for the upload tests.
- `.github/workflows/`: `ci.yml`, `e2e.yml`, `secret-scan.yml`, `security.yml`, `smoke.yml`. `.githooks/pre-commit`: secret scan.

## Entry points
- `app/page.tsx` renders `components/sentria/auth-gate.tsx`, which shows the sign-in screen or `app-shell.tsx` and the views.
- `app/t/[token]/page.tsx` renders `field-task-page.tsx`: public, sends no account, the token is the only credential.

## Data flow
- All backend calls go through `apiFetch` in `lib/api.ts`, which adds the Supabase token. `API_BASE` defaults to the Render URL; `NEXT_PUBLIC_API_URL` overrides it. Never hardcode a backend URL elsewhere.
- Several routes answer HTTP 200 with an error code. Read them through `lib/crm.ts` and `readList` in `lib/answer.ts`.
- Some settings are kept in the browser (localStorage), and the keys in `ACCOUNT_KEYS` (`lib/account.ts`) are synced to the account.

## Auth and permissions
- Supabase Auth, client in `lib/supabase.ts` (anon key, public by design). What it may read is set by the row-level security in `supabase/001_accounts.sql`.
- Plan, trial and admin flags in localStorage only drive the UI. The server enforces plan, admin and limits. A client check is never security.
- Admin screens sit behind `admin-guard.tsx`; the real check is on the backend.

## External integrations
- Backend API on Render. Supabase Auth. Vercel (hosting, analytics script in production).
- Stripe (`lib/stripe-js.ts`, `lib/billing.ts`, `pay-dialog.tsx`) and M-PESA, both through the backend.
- Error tracking (`lib/error-tracking.ts`, Sentry browser) and product analytics (`lib/analytics.ts`), off until a key is set.

## Critical business logic
- Plan numbers and capabilities come from the backend `GET /plans` (`lib/plans.ts`, `lib/entitlements.ts`). Never write a plan number in a component.
- Money: `lib/value-at-risk.ts` (`valueAtRisk`, `lossPerHour`). Only a `value` with a `currency` is money.
- Language: every string is French and English through `tx(fr, en)` or `localized()`.

## Restricted: do not edit by hand
- `lib/icons.tsx`, `lib/icon-data.ts` (generated by `scripts/build-icons.mjs`). `lib/alert-icon-data.ts` and `lib/site-icon-data.ts` also look generated by `scripts/build-alert-icons.mjs` and `build-site-icons.mjs`; read the script before touching them.
- `pnpm-lock.yaml` and `package-lock.json`: change only through the tools, and keep both in step.
- `next.config.mjs` security headers, `.githooks/`, `.github/workflows/`, `supabase/*.sql`: ask before changing.
- Deploy settings (Vercel), production data and secrets: never from a coding session.
- Third-party skill folders under `.claude/skills/` stay out of commits.
